Part 1Two Tools

同じ仕事を頼んでも、返ってくるものが違う

Microsoft 365 Copilot ─ 社内につながっている
  • Teams・Outlook・Word・Excel と統合されている
  • 社内ファイル・会議ログ・メールを横断できる
  • 見えるのは自分に権限のある範囲だけ（RBAC準拠）
来週の商談準備を Copilot に頼むと
来週商談のA社について、過去のメール・提案書・議事録を 横断して、経緯と先方の懸念点をまとめて。 出典（ファイル名・日付）も添えること。
ChatGPT ─ 考える力と生成量がある
  • 案の幅、文体の調整、批評。壁打ち相手になる
  • 画像・図表・手書きメモを読ませられる
  • 知っているのは渡した情報＋一般知識＋Web だけ
同じ商談準備を ChatGPT に頼むと
「価格が高い」という懸念への切り返しを、値引き以外で、 相手の不安の種類別に5つ挙げて。 それぞれ逆効果になる場面も一文で添えること。

優劣ではなく守備範囲の違いです。同じ商談準備でも、頼めることが最初から別。だから両方を持つ意味があります。

1
#役割
誰として答えるか。専門家を指定すると語彙と観点が変わる。
2
#命令
やってほしいことを一文で。ここだけ書くのが「ふつうの使い方」。
3
#文脈
自社の状況。ここを書くと一般論が自分ごとの答えになる。
4
#制約事項
やってほしくないことを先に潰す。やり直しがいちばん減るのはここ。
5
#出力指示
形式と数。「3製品」と書かないと数が揃いません。

全部書く必要はありません。うまくいかないときに、足りない見出しを1つ足す。それだけで直ります。

Part 2Governance

越えてはいけない線は、3本だけ

Access

権限は変わらない

見えてはいけない資料が出てきたら、それは AI の問題ではなく元の権限設定の問題。すぐ管理者へ。

Confidential

社外AIに入れない

社外秘・個人情報・未公開の数値を、社外の汎用AIに貼らない。社内データの仕事は Copilot 側で完結させる。

IP

生成物を確認する

出てきた文章・画像をそのまま社外公開しない。人が確認する工程を公開フローに1つ足す。

社外に出す前の、自己点検プロンプト
この文章に、社外に出せない情報が含まれていないか指摘して。 対象は「未公開の数値」「個人名」「取引先の固有条件」の3種類。 該当箇所をそのまま引用して示し、判断に迷うものは 「要確認」として分けて挙げること。

「怖いから使わない」ための話ではありません。ここを押さえた人だけが、遠慮なく踏み込めるという話です。

効く GPTs の共通点
  • 資料を持たせる。社内マニュアルを添付した瞬間、汎用AIが社内ツールに変わります。

  • 締めを固定する。「必ず担当部署を明記」で、社内展開できる品質になります。

AppendixA-03 / Marketing

マーケティング・企画

1. ファクトチェック ─ 必ず別チャットで実行する
あなたはファクトチェッカーです。以下を検証対象として扱い、 内容を擁護せず批判的に点検してください。 #依頼 1. 「事実主張」だけを抽出し番号付きリストに。事実主張とは 数値・固有名詞・年次・順位・因果関係を含む検証可能な文。 意見・推奨・一般論は除外 2. 各主張を表に。列は 主張 / 検証に必要な一次情報 / 確認先 / 判定（検証可能・出典不明・検証不能）/ 誤っていた場合の事業判断への影響（大中小） 3. 「出典不明 かつ 影響大」を優先度順に並べ、検証するまで 意思決定に使ってはいけない旨を明記 4. 調査会社レポート名・統計名は実在の自信度を添え、 中以下は捏造の可能性が高いと警告 #制約 - 「概ね正しいと思われます」のような曖昧な判定は禁止 - 検証していないものを「正しい」と判定しない
2. 競合比較表と空白地帯の特定
この市場の競合を「直接競合3社」「間接競合2社」 「代替手段2つ」に分けて挙げ、表にして。 列は 区分 / 名称 / 提供価値 / 主なターゲット / 価格帯 / 強み / 弱み・未対応領域 / 数値情報の確度 #制約 - 「弱み」は【構造的な制約】か【単なる未着手】かを 区別して書く。狙うべきは前者 - 売上・シェア等の数値は出典を併記。特定できない 場合は「非公開」と書く。推測値を書かない - 「代替手段：何もしない」を必ず含める
Caution

競合の売上・シェア・ユーザー数は捏造率が高い。企業名と提供内容までは使えますが、数値はIR資料等で必ず確認してください。

AppendixA-05 / People & Managers

人事・組織／管理職

1. サーベイ自由記述の分析 ─ カテゴリを先に決めない
#手順 1. 回答を読み、内容に基づいてカテゴリを抽出する （カテゴリは事前に指定せず、記述から立ち上げる） 2. 各カテゴリの件数を集計し、要旨を示す（原文を引用せず、 複数人に共通する内容を言い換えて記述） 3. 件数が2件以下は「少数意見」として別枠に全件列挙する （要約や統合をしない） 4. 「深刻度（高中低）×件数」で整理 5. この分析からは判断できない事項を列挙 #制約事項 - 原文に書かれていない原因・背景を推測しない - 個人が特定される記述は要旨に含めない - ハラスメント・差別・違法行為・安全上の危険を示唆する 記述は集計に混ぜず、件数のみ冒頭に出し、内容は 記載せず規定の窓口へ連携が必要と明記する
2. 1on1の論点整理 ─ 評価はさせない
あなたは1on1の準備を支援するアシスタントです。 評価や人事判断は行いません。 #出力指示 1. 前回からの差分（進んだ／止まっている／新しく出た） 2. 前回合意したアクションの状況と、障害 3. 今回話すべき論点（3つまで。優先順と理由） 4. 論点ごとの問いかけ案（各2つ。詰問にならない言い回し） 5. 今回は扱わないほうがよい話題と、その理由 #制約事項 - 本人の記述に無い内容を推測で補わない - 性格・資質・適性を評価しない。行動と成果物に限定 - 論点は「本人が次の2週間で動かせるもの」に絞る

1. 参照資料限定Q&A ─ 嘘をつかせたくない場面の基本形
#命令 以下の「参照資料」のみに基づいて、私の質問に回答して ください。 #参照資料 {{規程・ガイドライン・仕様書を貼る}} #回答の絶対ルール - 参照資料に書かれている内容のみを根拠とすること。 一般常識・他社事例・推測で補わないこと - 回答には必ず、根拠となる箇所を原文のまま引用すること - 記載が無い場合は「参照資料に記載なし」とだけ回答する - 記述が曖昧または矛盾している場合は指摘し、どう解釈 しうるかを両論併記する #出力形式 【回答】結論を2文以内 【根拠】資料からの引用（「」で囲む） 【備考】解釈の余地・確認が必要な点。無ければ「なし」
2. リライト・添削 ─ 必ず2ターンに分ける
【ターン1｜指摘のみ】 以下の文書をレビューし、修正はせずに問題点だけを 列挙してください。読み手は{{ }}、目的は{{ }}。 出力は4列の表のみ：No / 該当箇所（原文引用）/ 問題の種類 / 修正方針 種類は「事実の不明瞭さ／論理の飛躍／冗長／語調の 不一致／体裁」で分類。重要度順、最大10件。 【ターン2｜採用分のみ反映】 上記のうち No.{{ }} のみを反映して全文書き直して。 指摘していない箇所は原文のまま。元の主張・結論を 変えない。数値・固有名詞・日付は一切変更しない。

AppendixA-08 / Cautions

越えてはいけない線

場面やってはいけないこと代わりにこうする
履歴書・職務経歴書原本をそのまま外部AIに貼るA-04 の匿名化を、社内承認済み環境で先に通す。AIには「漏れの検出」だけを担わせる
書類選考・面接評価AIの判定をそのまま合否に使う判断は人が行う。四半期に一度 A-04 のバイアス監査をかける
1on1・面談生の会話記録を本人同意なく入力する本人が書いた振り返りシートのみを対象にする。健康・家庭事情の記述は入力から除外
サーベイ自由記述ハラスメント示唆を集計に混ぜる集計から外し、内容は記載せず規定の窓口へ即エスカレーション
調査・市場データ出てきた統計名や数値を資料に載せるA-03 のファクトチェックを別チャットでかけ、一次情報に当たる
社外秘・未公開情報顧客名・未公開の数値を外部AIに貼る社内データを扱う仕事は Copilot 側で完結させる（本編 P.12）

この6行は、社内スキル集の各プロンプトに付いている「注意」の欄を集めたものです。プロンプト本体より、こちらのほうが事故を防ぎます。
